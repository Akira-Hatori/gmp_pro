# core/dev 说明（面向初学者）

本文件为初学者整理 `core/dev` 目录的作用、相关名词通俗解释、如何用该目录进行开发的步骤、以及推荐的入门实验与调试要点。

## 重要名词解释（通俗、面向初学者）

- 环形缓冲 / Ring Buffer：一段固定长度的数组当作循环队列，写指针（iset）写入，读指针（iget）读取。常用于 ISR（中断）与主循环间传输字节数据，避免频繁分配内存。
- FIFO：先进先出（First-In-First-Out），环形缓冲就是一种 FIFO 实现。
- ISR（中断服务例程）：硬件事件（如串口收到字节）触发的处理函数。ISR 应尽量短，只做必要的读写（例如把字节放入 ring buffer）。
- HAL（硬件抽象层）：把具体 MCU/板子的外设操作封装成统一函数（例如 `gmp_hal_uart_write`），使上层代码与具体芯片无关。
- 半双工 / 全双工：半双工同一时刻只能收或发（例如 RS485），全双工可同时收发（普通串口）。
- SPI / I2C / UART / CAN：常见串行总线协议，各有帧结构与时序差异，`core/dev` 提供对应的接口原型。
- AT 命令：文本命令集（如 `AT+CMD`），常用于交互式控制与调试。本仓库提供 AT 命令解析框架。
- 缓冲池 / pool：用户提供的一块静态内存作为 ring buffer 的存储区域，避免运行时动态分配。
- 异步 / 同步：同步函数会阻塞直到完成；异步函数发起操作后立即返回，完成通过中断或回调通知。
- RT Shell / 解释器：运行时交互壳，可解析表达式、变量与函数调用，用于交互式调试与计算（仓库中有草案实现）。

## `core/dev` 做了什么（高层概述）

- 提供通信外设的抽象接口与工具，目标是把外设驱动（MCU 寄存器、SDK）与上层逻辑（AT 命令、RT shell、数据处理）解耦，便于复用。
- 主要内容：
  - `interface.h`：定义了 half-duplex、duplex、IIC memory、CAN 等接口结构与初始化函数原型。
  - `peripheral_port.h`：定义了 `gmp_hal_spi_*`、`gmp_hal_uart_*`、`gmp_hal_iic_*` 等 HAL 原型，板级代码需要实现这些函数。
  - `ring_buf.h`：环形缓冲的声明与操作函数（生产者/消费者场景）。
  - `at_device.h`：AT 命令框架的结构体、接收 ISR 接口与调度函数。
  - `rtshell`：运行时 shell 的草案（表达式解析与执行的思路和部分接口）。

## 如何使用 `core/dev` 来开发（面向初学者，按步骤）

- 第 0 步（准备）：确保你有能编译并在目标板跑最小固件的工具链和环境（能跑串口打印或 LED 灯闪烁）。
- 第 1 步（读接口）：阅读 `interface.h` 与 `peripheral_port.h`，理解上层期望的结构和 HAL 函数名/参数。
- 第 2 步（实现 HAL）：在你的板级目录（如 `vcore` 下的板子目录）实现 `gmp_hal_uart_write`、`gmp_hal_uart_read` 等函数，内部调用 MCU 的串口驱动或 SDK。
- 第 3 步（使用环形缓冲）：在串口驱动里定义 `ringbuf_t` 并使用用户预先分配的 `mem_pool`，在 UART RX ISR 中把字节写入 ring buffer，主循环/任务中读取并处理。
- 第 4 步（集成 AT 框架）：定义 `at_device_cmd_t` 命令表，调用 `at_device_init()`，在 ISR 中把接收数据交给 `at_device_rx_isr()`，在主循环中周期性调用 `at_device_dispatch()` 来解析并执行命令。
- 第 5 步（添加 RT shell）：如果需要更灵活的交互式表达式计算，可实现或扩展 `rtshell` 模块，将文本解析为表达式并 eval。
- 第 6 步（测试）：先实现串口回显（echo）确保 ISR → ringbuffer → 主循环流程正确，然后实现简单 AT 命令（如 `AT+VER?`、`AT+SETKp=`）验证整体链路。

## 初学者推荐的入门实验（按优先级）

- 实验 A（必做）：实现 UART HAL，使终端输入经 ISR 写入 ring buffer 并在主循环回显。验证数据链路。
- 实验 B（进阶）：在 A 的基础上集成 `at_device`，实现 `AT+VER?`（返回版本）和 `AT+ECHO=<text>`。
- 实验 C（理解总线）：实现并测试简单的 SPI 写函数，或在两个设备/回环中验证 SPI 数据传输。

## 学习路径建议（顺序）

- 学习串口、中断与环形缓冲（理解 ISR 与主循环如何协作）。
- 学习 HAL 设计模式（如何封装具体 MCU 驱动为统一接口）。
- 学习 AT 命令解析器的状态机与行缓冲实现。 
- 若做电机控制：学习控制理论（PID/矢量控制）以及嵌入式 DSP 编程（定点/浮点）。

## 调试技巧与注意事项（快速清单）

- ISR 里尽量只做最小工作：读取数据并放入 ring buffer，不要在 ISR 里做复杂运算或阻塞调用。
- 环形缓冲容量通常保留一个位置来区分“满”与“空”。
- 主循环或独立任务定期调用 `at_device_dispatch()` 做命令解析。
- 如果使用 DMA/多线程，注意并发安全和 volatile 正确使用。
- 开发初期优先做“可观测”功能（串口回显、AT+VER?），便于定位问题。
