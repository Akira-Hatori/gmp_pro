# PM 模块概览（面向初学者）

本文件面向刚接触电机控制与嵌入式开发的初学者，基于仓库中 `core/pm` 目录下的说明和示例，通俗地介绍该目录做了什么、涉及的重要名词，以及如何利用该模块开展开发与练习。

## 重要名词（通俗解释）
- 调度器（Scheduler）：管理一组“任务”的小程序，决定哪个任务何时运行。这里是协作式调度器，任务需要主动尽快返回，不会被强制中断。
- 任务（Task）：你注册给调度器的函数或结构体，包含执行代码、周期和状态等信息。
- 周期（period）：任务期望的运行间隔，通常以毫秒为单位。
- 系统 Tick（system tick）：由硬件定时器或芯片支持包（CSP）提供的时间计数器，调度器用它判断任务是否到期。
- dispatch（调度/分发）：调度器的核心函数，放在主循环里反复调用，负责挑选并执行一个任务。
- 非阻塞 / 协作式（Non-blocking / Cooperative）：任务必须快速返回 CPU；若长时间运行会阻塞所有其他任务。
- `GMP_TASK_BUSY` / BUSY（忙）：任务返回“忙”状态，表示尚未完成但不想阻塞，调度器会优先再次调用它直到返回 `DONE`。
- `GMP_TASK_DONE` / DONE（完成）：本轮执行完成，调度器更新最后运行时间并在下次周期到时再次调度。
- `run_state`（运行状态）：任务内部可用的状态变量，配合 BUSY 使用可把长操作拆分为多个小步骤实现分段执行。
- watchdog（看门狗）：硬件定时器，若系统长时间不喂狗会复位。用 BUSY 分段执行能避免喂狗失败。
- 上下文切换（Context switch）：抢占式系统中保存/恢复任务执行状态的操作，协作式系统开销小。
- CSP（Chip Support Package）：芯片相关的底层代码，例如提供获取系统 Tick 的函数。
- State Machine（状态机）：用有限状态与转移描述组件行为的模式，适合顺序逻辑。
- Workflow（工作流）：更高层的流程管理工具，用于描述多个步骤或路径的顺序/并行执行。

## `core/pm` 文件夹做了什么（高层总结）
- 提供一套轻量的“处理管理”工具（Processing Management），适用于资源受限的嵌入式场景。
- 包含一个轻量级、非抢占式的任务调度器，支持任务周期、使能、运行状态等基本特性。
- 支持把长任务拆分为多个短步骤的机制（通过 `GMP_TASK_BUSY` / `GMP_TASK_DONE` 与 `run_state`）。
- 附带状态机（`state_machine.h`）和工作流（`workflow.hpp`）模块，用于更复杂的流程或状态管理。
- `timing_manager.h` 提供基于 Tick 的时间管理辅助。

### 目标场景
该模块面向没有或不想使用 RTOS 的 MCU 项目，通过主循环高频调用 `dispatch` 实现伪并行、多任务与有序流程控制，资源占用低、实现简单。

## 关键文件（建议先读）
- `readme_function_scheduler.md`：调度器用户手册，包含示例与工作原理，是入门首读文件。
- `readme.md`：模块总体说明，介绍 workflow 与其他模块。
- `scheduler.hpp` / `function_scheduler.h`：调度器接口与实现相关头文件，查看具体 API 和结构体定义。
- `state_machine.h`：状态机支持。
- `timing_manager.h`：时间管理辅助。
- `workflow.hpp`：工作流模块。

## 如何利用这个文件夹进行开发（面向初学者、逐步实践）
1. 阅读与理解（30–60 分钟）：先读 `readme_function_scheduler.md` 的快速集成与示例代码，理解调度器的工作模型（`dispatch` 在主循环中运行）。
2. 准备系统 Tick（必要）：确认工程中有 `gmp_base_get_system_tick()`，该函数返回系统 ms 计数；若没有，可基于 SysTick 或硬件定时器实现。
3. 简单示例：LED 闪烁（实战演练）：按手册示例定义任务数组（如 blink、monitor），在 `main` 中初始化调度器、添加任务，并在 `while(1)` 中高频调用 `gmp_scheduler_dispatch`。
4. 学会拆分长任务（BUSY 模式）：写一个模拟的长耗时任务（比如 ADC 转换：触发->等待->读取），用 `run_state` + 返回 `GMP_TASK_BUSY` 的方式分步处理，避免阻塞主循环与看门狗。
5. 使用 `user_data` 传递上下文：把任务需要的参数打包到结构体，放入 `user_data`，在任务回调中通过指针访问，避免全局变量。
6. 进阶：状态机与工作流：当单个任务需要复杂流程或多个阶段时，参考 `state_machine.h` 与 `workflow.hpp`，把任务逻辑抽象成状态机或工作流。
7. 测试与调试：在开发板上用 LED/串口/逻辑分析仪观察任务执行节奏；在硬件上优先验证 blink、ADC 等小例程。
8. 扩展与注意事项：如果任务数超出默认上限，定义宏 `GMP_SCHEDULER_MAX_TASKS` 提升上限（注意内存）。若需要抢占式特性或线程隔离，考虑使用 RTOS。

## 给你的学习建议与练习路径
- 先动手跑通一个 blink 示例（最直接学会调度机制）。
- 理解“协作式 vs 抢占式”调度的区别，避免任务中使用长阻塞函数（如 busy-wait）。
- 学习如何用 `run_state` 将长流程拆分成若干小步骤（示例手册已有）。
- 逐步阅读 `state_machine.h` 与 `workflow.hpp`，当需要管理复杂多步骤时再引入。
