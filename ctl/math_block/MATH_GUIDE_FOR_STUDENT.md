## 1. 为什么我们需要一个专门的数学库？

作为初学者，你可能会问：*“C语言不是自带 `<math.h>` 吗？为什么还要自己写一套？”*

这是嵌入式开发中的第一个重要概念。

### 1.1 性能（Performance）
标准库的 `sin()`, `cos()`, `sqrt()` 主要为通用计算机设计（你的笔记本电脑 CPU 可以在 1ns 内跑完复杂的指令）。但在嵌入式 MCU（微控制器）中：
*   **资源受限**：没有那么多时间去跑泰勒级数展开。
*   **实时性**：在电机控制中，中断服务函数（ISR）必须在 50微秒（20kHz）甚至更短的时间内跑完。如果一个 `sin()` 就要耗时 10微秒，电机就转不稳了。

### 1.2 可移植性与硬件抽象（Portability & Abstraction）
这是本模块最精彩的设计之一。请关注 `ctrl_gt` 这个类型。
*   **STM32G4/H7 (Cortex-M4/M7)**：拥有 FPU（浮点运算单元）。`ctrl_gt` 会被定义为 `float`，并调用 ARM 官方优化的 `arm_dsp` 库指令（一条汇编指令就能完成乘加运算）。
*   **TI C2000 (F28335/F280049)**：如果不使用 FPU 或者为了兼容老代码，`ctrl_gt` 可能是 IQMath 格式（定点数）。
*   **FPGA / ASIC**：可能是自定义的定点位宽。

这一层抽象（Abstraction Layer）让你写的电机控制算法（PID, FOC）可以一字不改地移植到所有平台上。

### 1.3 内存管理（Memory）
标准库的矩阵运算（如 C++ Eigen, Python NumPy）大量使用 `malloc/new` 在堆（Heap）上分配内存。
*   **嵌入式大忌**：在高速 ISR 中绝对禁止动态内存分配！因为你无法预测 `malloc` 需要多少时间，也容易造成内存碎片导致系统崩溃。
*   `math_block` 里的所有向量、矩阵，全部基于**静态数组**实现，0 动态内存开销，确保了代码的绝对健壮性。

## 2. 文件夹深度导读

让我们打开每一个子文件夹，看看里面藏着什么宝藏。

### 2.1 `ctrl_gt/` —— 系统的“地基”
*   **`arm_cmsis_macros.h`**: 如果你用的是 STM32，这里面的宏会将数学运算映射到 ARM 的 DSP 库。
    *   例如：`ctl_mul(a, b)` -> `a * b` (在 Cortex-M4F 上这是一条指令)。
*   **`iqmath_macros.h`**: 如果你在用老旧的定点 DSP，这里会将 `ctl_mul(a, b)` 映射为 `_IQmpy(a, b)`。
    *   *微机原理知识点*：定点数的乘法不仅是整数相乘，乘完还需要右移代码中的 Q 值（例如 Q24 格式）。如果不理解这个，你的结果会放大 16,777,216 倍。

### 2.2 `coordinate/` —— FOC 的核心（必读！）
`coord_trans.h` (Coordinate Transformation) 是你必须逐行研读的文件。它是名为“矢量控制”的魔法的发生地。

*   **Clarke 变换 (`ctl_ct_clarke`)**:
    *   **输入**：三相电流 $I_a, I_b, I_c$（互差120度）。
    *   **输出**：两相静止电流 $I_\alpha, I_\beta$（互差90度）。
    *   **代码细节**：你会发现代码里用的是 `CTL_CTRL_CONST_ABC2AB_ALPHA` (2/3) 等常量。
    *   *电机学思考*：为什么系数是 2/3 而不是 $\sqrt{2/3}$？这涉及“等幅值变换”与“等功率变换”的区别。这里使用的是等幅值变换，意味着变换后的电流幅值等于物理电流幅值，物理意义更直观。

*   **Park 变换 (`ctl_ct_park`)**:
    *   **输入**：$I_\alpha, I_\beta$ 和当前电机角度 $\theta$ (sin/cos)。
    *   **输出**：旋转坐标系电流 $I_d, I_q$。
    *   **物理意义**：一旦进入 dq 坐标系，交流电机就变成了“直流电机”。控制 $I_q$ 就是控制转矩，控制 $I_d$ 就是控制磁通（弱磁）。

*   **SVPWM 部分（如果有）**:
    *   这里通常涉及大量的逻辑判断（扇区判断）。把圆分成6个扇区，计算 $T_1, T_2, T_0$ 作用时间。这是数字信号处理的经典案例。

### 2.3 `vector_lite` & `matrix_lite` —— 轻量级线性代数
*   **`vector3.h`**: 定义了三维向量。
    *   为什么需要它？三相电 $(A, B, C)$ 本质上是一个三维空间中的矢量。
*   **`matrix3.h`**: 定义了 3x3 矩阵。
    *   **应用场景**：当你深入到“高频注入”、“无感观测器（Luenberger, Kalman Filter）”、“参数辨识（RLS）”时，你需要解矩阵方程。这个库让你在单片机里也能优雅地写出 `Ax = b`。

### 2.4 `complex_lite/` —— 复数与四元数
*   **`complex.h`**: $\alpha\beta$ 轴系本质上就是复平面。
*   **`quaternion.h` (四元数)**:
    *   你可能觉得这是无人机用的。但在高级电机控制中，特别是涉及机械臂末端姿态解算，或者使用 IMU（惯性测量单元）辅助电机控制时，四元数比欧拉角（Euler Angles）更不容易产生死锁（Gimbal Lock），计算效率也更高。

### 2.5 `const/` —— 效率的源泉
*   **`math_ctrl_const.h`**:
    *   永远不要在代码里写 `1 / sqrt(3)`！
    *   这就好比每次做饭都要先去种麦子磨面粉。我们直接把计算好的面粉（常量）放在这里。
    *   **`float2ctrl`**: 这个宏确保了当你切换编译器设置时，常数也会自动变成对应的格式（比如自动变成定点数整数）。

## 3. 开发者手册：如何使用本模块

### 3.1 编码规范：`GMP_CTL_OUTPUT_TAG`
你会看到很多函数参数里有这个宏：
```c
void ctl_ct_clarke(const ctl_vector3_t* abc, GMP_CTL_OUTPUT_TAG ctl_vector3_t* ab);
```
在 C 语言中，指针既可以是输入也可以是输出。为了避免混淆，我们用这个空的宏标记**输出参数**。请务必遵守这个约定，这是编写高质量嵌入式代码的体现。

### 3.2 避免隐式类型转换
始终使用 `ctl_mul`, `ctl_add` 等宏进行计算，而不要混用 `*` 和 `+`，尤其是当你可能在定点和浮点平台间切换时。
*   **错误写法**：`res = a * b + c;` (在定点库下可能炸裂)
*   **正确写法**：`res = ctl_add(ctl_mul(a, b), c);`

### 3.3 学习路线图（你的作业）

**第一周：建立坐标系观念**
1.  手动推导 Clarke 和 Park 变换矩阵。
2.  阅读 `coordinate/coord_trans.h`，将你的推导公式与代码一一对应。
3.  **调试练习**：编写一个简单的 C `main` 函数，模拟输入一组三相正弦波数据（$I_a = \sin(t), I_b = \sin(t-120^\circ), I_c = \sin(t+120^\circ)$），调用库函数，打印出 $I_d, I_q$。观察它们是不是常数？（如果是常数，通过！说明变换正确）。

**第二周：理解数值精度**
1.  了解 IEEE 754 浮点数标准。
2.  阅读 `ctrl_gt/` 下的宏定义。
3.  **思考**：在 `arm_math.h` 里，`sqrt` 是怎么实现的？它比标准的 `sqrt` 快在哪里？（通常利用了牛顿迭代法的硬件指令）。

**第三周：进阶算法**
1.  尝试阅读 `matrix_lite`，思考如何用它来实现一个简单的“最小二乘法”？（这是电机参数自辨识的基础）。

## 4. 常见疑问 (Q&A)

**Q: 我发现代码里很多 `inline` 函数，会增加代码体积吗？**
A: 会微量增加（空间换时间）。但在电机控制中，CPU 的**时间**比 Flash 的**空间**珍贵得多。函数调用压栈出栈的开销在 20kHz 频率下是不可忽视的浪费。

**Q: 为什么 Clarke 变换的代码里有个 `phase_0`？**
A: 这是“零序分量”。在理想的三相四线制或者三相三线制平衡系统中，它通常是0。但在故障检测或特定的 SVPWM 调制策略中，零序分量非常重要。不要忽略它。

**Q: `Negative Sequence` (负序) Park 变换是干嘛的？**
A: 当电网电压不平衡（三相不对称）时，通过正负序分离控制，可以让电机在电网故障时依然平稳运行。这是进阶的高级功能，初学阶段可以先跳过。
